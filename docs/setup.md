# Локальный запуск и настройка

[Обзор проекта](../README.md) · [Архитектура](architecture.md) · [Проверки](verification.md)

Инструкция помогает воспроизвести проект в собственной среде. Она не описывает развёртывание сервера для круглосуточной работы. Публичная форма и интерактивная демостраница в текущий портфолио-релиз не входят.

## Требования

- Python 3.13 — версия локальной проверки.
- PostgreSQL или Supabase с приватным серверным подключением.
- n8n с PostgreSQL, OpenAI, Telegram и выполнением Python Native Code.
- Ключ OpenAI, Telegram-бот и чат для контролируемых тестов.
- Node.js для проверки JavaScript-части экспортов.

Версия n8n в репозитории не закреплена как подтверждённая для новой установки. Перед переносом выберите конкретную версию и проверьте совместимость; `latest` не является воспроизводимой настройкой.

Worker содержит `Prepare Manager Message` на Python Native. При самостоятельном размещении нужен совместимый Python task runner. Наличие Python рядом с Flask само по себе не делает этот узел доступным в n8n.

Служебная база n8n хранит workflow, credentials и выполнения. Это другая задача, чем PostgreSQL/Supabase с заявками проекта. Они требуют отдельных настроек.

## 1. База заявок

Для **новой пустой базы** выполнить по порядку:

1. [db/001_init.sql](../db/001_init.sql) — таблица, индексы и `enqueue_lead_v1`.
2. [db/002_restrict_public_access.sql](../db/002_restrict_public_access.sql) — ограничение публичного доступа.

`001_init.sql` не является миграцией поверх существующей `public.leads`. Если таблица уже есть, сначала разберите структуру и сохраните резервную копию. Подробности — в [db/README.md](../db/README.md).

Подключение n8n должно иметь серверные права для работы с таблицей и функцией. Публичный Supabase API key для этого маршрута не подходит.

## 2. Workflow n8n

Импортируйте каждый JSON в отдельный новый workflow: импорт на существующий холст может добавить узлы к имеющимся. Экспорты выключены и обезличены; credentials, адресат и ссылки на Worker назначаются в вашей среде.

| Workflow | Что настроить |
|---|---|
| [Worker](../n8n/worker.json) | PostgreSQL credentials всем узлам базы; OpenAI и Telegram credentials; тестовый чат вместо `REPLACE_WITH_MANAGER_CHAT_ID`; доступность Python Native |
| [Intake](../n8n/intake.json) | PostgreSQL; Header Auth с заголовком `X-Webhook-Secret`; в `Wake Worker` выбрать импортированный Worker без ожидания завершения |
| [Recovery](../n8n/recovery.json) | В `Run One Worker` выбрать тот же Worker с ожиданием завершения; проверить расписание каждые пять минут |

Проверить таймаут Worker и Recovery — 180 секунд, модели — 45 секунд. Ограничения установки или тарифа могут отличаться. Дополнительные повторы модели отключены; попытки учитываются логикой заданий.

В экспорте выбрана `gpt-5-mini`. Доступность зависит от аккаунта OpenAI; замена требует повторной проверки структурированного ответа и поведения квалификации.

**До включения Recovery оцените квоту:** каждые пять минут — 8 640 запусков за 30 дней даже без заявок. Для n8n Cloud это нужно сопоставить с актуальными правилами тарифа; Starter с 2 500 запусков недостаточен. На собственном сервере нужно учитывать ресурсы и сопровождение.

Проверьте настройки после импорта: JSON не гарантирует перенос всей конфигурации среды. Опубликуйте workflow так, чтобы Intake и Recovery могли вызывать Worker. Сохраните Production URL Intake для Flask.

## 3. Форма Flask

Из корня репозитория:

```sh
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

В локальном `.env` заполнить:

| Переменная | Значение |
|---|---|
| `N8N_WEBHOOK_URL` | Production URL Intake, не временный Test URL |
| `N8N_WEBHOOK_SECRET` | Значение Header Auth `X-Webhook-Secret` |
| `PORT` | Локальный порт, по умолчанию 5050 |
| `FLASK_DEBUG` | `0` |

Рабочий `.env` в Git не добавлять. База, OpenAI и Telegram подключаются в n8n; Flask их credentials не нужны.

```sh
python serve.py
```

Открыть `http://127.0.0.1:5050`. Waitress слушает локальный интерфейс и использует четыре потока. Эта команда не делает форму доступной в интернете.

## 4. Проверки

```sh
python -m unittest discover -s tests -v
node tests/check_workflows.cjs
```

Локальные проверки не отправляют заявки во внешние сервисы. Проверки JavaScript читают экспорты и запускают выбранные Code-узлы; они не подтверждают credentials или фактическую работу установки n8n.

Контролируемый прогон полной цепочки выполняется отдельно на вымышленных данных. Он расходует API и отправляет уведомление: сначала убедитесь, что чат предназначен для теста.

Проверить новую заявку, запись в базе, результат AI и доставку; затем повтор с тем же UUID без второй записи, конфликт с изменёнными данными и отказ при невалидном вводе. Recovery проверяется на отдельных вымышленных заданиях без случайной отправки менеджеру.

Исторические результаты — в [verification.md](verification.md). Новая среда требует собственной проверки. Для реальной эксплуатации дополнительно нужны HTTPS, постоянный запуск, ограничение запросов, резервные копии, наблюдение за ошибками и правила хранения данных.
