# Проверки

Проверено 16 октября 2026. Результаты относятся к локальному Flask, действующему n8n Cloud и Supabase. Реальные данные заявок в отчёт не включены.

## Автоматические локальные проверки

- 26 Python-тестов: валидация, согласие, honeypot, ошибочные ответы сервиса, повтор, конфликт и Telegram-шаблон.
- 51 сценарий проверки данных Intake на JavaScript.
- 7 сценариев выбора исхода AI: успех, временная ошибка, постоянная ошибка, parser error, лимит попыток и Retry-After.
- Проверка ссылок между узлами и компиляция JavaScript Code-узлов.

## PostgreSQL

Девять интеграционных проверок прошли на вымышленных данных:

1. Приём, повтор и конфликт оставляют одну строку.
2. Активное владение задачей исключает повторный захват.
3. Старый токен не позволяет записать результат.
4. Повтор не забирается раньше `processing_next_at`.
5. Просроченная AI-задача захватывается с новым токеном.
6. Исчерпание попыток переводит заявку в ручную проверку.
7. Telegram-задача использует отдельный токен и время повтора.
8. Последняя неоднозначная попытка Telegram останавливается на лимите.
9. Два одновременных запроса с одним UUID дают один `accepted` и один `duplicate`.

Большинство изменений выполнено внутри откатываемой транзакции. Для конкурентной проверки использовалась отдельная запись с отключённой доставкой и отложенной обработкой; после теста она удалена. Эти проверки не вызывают OpenAI и Telegram.

Bootstrap базы проверен в отдельной временной схеме с последующим откатом. Пройдены приём, повтор и конфликт на заново созданной таблице.

## Работающий маршрут

- Новая вымышленная заявка через Flask: HTTP 202, запись в PostgreSQL.
- Worker: `completed`, одна AI-попытка.
- Telegram: `sent`, одна попытка, возвращён `message_id`. Отправлено одно согласованное тестовое уведомление.
- Повтор той же заявки: HTTP 202 и `duplicate=true`.
- Другие данные того же UUID: HTTP 409.
- NUL в описании: HTTP 400 до n8n.
- После восьми дополнительных повторов Telegram остался в состоянии `sent` с одной попыткой.
- Recovery обработал три задания с исчерпанными AI-попытками: `needs_review`, доставка отключена. Четвёртый вызов обнаружил пустую очередь и завершил цикл. Тестовые задания затем удалены.
- После включения RLS и отзыва публичных разрешений повтор через Flask → n8n остался успешным. Публичная роль не имеет SELECT, INSERT и EXECUTE enqueue-функции.

## Измерения HTTP

| Сценарий | Время |
|---|---:|
| Первый успешный приём новой заявки | 2320,9 мс |
| Первый повтор | 1118,5 мс |
| Конфликт UUID | 523,8 мс |
| Локальный отказ при NUL | 3,2 мс |
| Медиана отдельной серии из 8 повторов | 383,45 мс |

В отдельной диагностике медиана HTTP без базы с переиспользованием соединения составила 191,45 мс, с `SELECT 1` — 217,5 мс. Диагностические workflow не используются в рабочем маршруте и убраны из рабочего списка.

## Не проверено

Реальный сетевой обрыв ответа OpenAI/Telegram, остановка процесса n8n во время отправки, длительная нагрузка и внешний сайт с HTTPS. Подмена состояния в базе проверяет правила recovery, но не заменяет эти сценарии. SLA и отсутствие повторных Telegram-сообщений не заявляются.
